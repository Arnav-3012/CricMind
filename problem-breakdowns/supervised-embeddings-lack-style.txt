PROBLEM: supervised player embeddings (cric2vec) lose to target-encoded stats and encode little player style; decide what to do so Phase 4 archetypes for batter-vs-bowler matchups rest on a sound representation
DOMAINS: ML(representation learning, supervised embeddings) + stats(reliability, ablation) + research process(pre-registration)
IN: Cricsheet T20 ball-by-ball, train <=2023, holdout 2023, val 2024, test 2025-26; seed-42 embeddings (dim 8); per-player stats   OUT: a player representation to cluster into archetypes + an honest account of why   SUCCESS: probe R2/reliability, bootstrap ARI of clusters, Phase 5 test matchup log-loss (touched once)
GIVENS: ~1.6M train balls; ~1.1k batters / 1.2k bowlers with >=300 balls; val gate result cric2vec 1.4307 vs LGBM+stats 1.4246 (+0.0061 [0.0055,0.0067]); E(ids add to MLP, holdout)=0.0018 [0.0010,0.0026]; probe ratio batter 0.16, bowler 0.09; sequence gain 0.0008 (<0.002, no Phase 3b); MPS laptop
HIDDEN_REQS: no selection on val/test (val already judged cric2vec, test is Phase 5); every variant pre-registered in decisions.md; embeddings needed only for clustering, not prediction
ASSUMPTIONS: probe stats (SR, dot%, boundary%, wicket rate per phase) are a fair definition of "style" -> they are what the stats arm clusters on
OPEN_QS: is a lite-context embedding more stable under bootstrap than stats vectors? | is factorising the player x phase x outcome count profile (SVD/NMF) enough to count as a "learned" arm?

BIG_PICTURE: not a tuning problem; an objective problem. The embedding was trained to predict the next ball GIVEN rich context (batter_runs, balls_faced, over, bowler_balls_bowled), so the context explains away identity and the embedding keeps only the residual (what a player adds after the situation is known). Archetypes need style, which the context partly absorbed. Per-player target-encoded rates are near-sufficient statistics of each player's outcome distribution, and the data's own noise caps any representation.
CUT: diagnosis ladder: broken? -> where is the loss? -> why? -> what does the data allow? -> how to judge a fix -> how to act honestly. Leaves 1,2,5 done; 3,4,6 open.

KEY_FORMULAS:
gap = (L_M1 - L_M0) + (L_M0 - L_T0) + (L_T0 - L_T1) = -E + W + S
rho = 2r / (1 + r)   (Spearman-Brown, r = split-half correlation)
probe ratio = CV_R2 / rho
logloss = -(1/N) sum_i ln p_i(y_i)
GLOSSARY: E=log-loss gain from player ids in the MLP; W=MLP-vs-trees gap on context alone; S=stats' gain to trees; explaining away=network uses the easier of two redundant inputs; lite-context=embedding model with ids + phase only; ARI=adjusted Rand index; holdout=2023 train year used for every choice
